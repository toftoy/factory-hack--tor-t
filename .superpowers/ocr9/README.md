# Round 9 harness and raw results — the ROI crop stage

Everything behind the round-9 section of `../ocr-investigation-report.md`
(sections 61-67). Committed for the same reason round 8 committed its own: the
numbers in the report can be re-derived from the raw runs here rather than
trusted.

Round 9 measures a **change to `gjenglemt/src/ocr.ts`**, not just the pipeline as
it stood, so it carries two full 128-image runs: the change, and the unchanged
pipeline re-run in the same session on the same machine (see section 66 — this
machine is slower than round 8's, and comparing against round 8's stored numbers
would have flattered the change).

## Images

**This round did not generate a new test set.** It reuses round 8's 128 composed
photos exactly as they were, which is what makes every before/after here a paired
comparison rather than two samples. They are regenerated by round 8's scripts
(`../ocr8/`, on that round's investigation branch) from deterministic seeds.

Verified before use: the distribution matches round 8's report exactly (near 26 /
mid 39 / far 44 / vfar 19; cap-height slices >=30px 26, 20-30px 39, 12-20px 44,
<12px 19), and re-running `compose8.mjs 0 4` reproduces the clean-background
frames **byte for byte**. One caveat found and worth carrying forward: the
**fabric** backgrounds are *not* byte-reproducible, because `compose8.mjs` builds
them from `sharp`'s gaussian `noise`, which is not seeded — a regenerated fabric
frame has the same texture statistics but a different draw. 30 of 128 images are
fabric.

## Reproducing

Needs `playwright-core` in scope, a Chromium at `/opt/pw-browsers/chromium`,
round 8's `img/` directory, and the cached `nor` language data. `run9.mjs`,
`roidump.mjs` and `croplab.mjs` hard-code the worktree path to the app and the
scratchpad paths; all three need editing elsewhere.

```
# step 1 — is there an ROI signal at all? (no app build needed)
node roidump.mjs                 # -> roidump.json   word boxes from the two primary passes
node roicheck.mjs                # what ROI the rule derives from them
node spancheck.mjs               # how big the located label is, as a fraction of the frame
node roipeek.mjs R008 R128       # the raw boxes for one image

# step 2 — does cropping to it help, and at what scale?
node croplab.mjs                             # -> croplab.json   targets 20/30/45/60px
TARGETS='16,20,24,30,20:plain,24:plain' node croplab.mjs croplab2.json

# step 3 — the whole app, before and after
npm run build && npx vite preview --port 4339   # in gjenglemt/
node run9.mjs 0 128                             # -> results9.jsonl
# ...then rebuild with src/ocr.ts restored from main, serve on 4340, and:
APP=<baseline app> TARGET_URL=http://localhost:4340/?debug=1 OUT=results9base.jsonl node run9.mjs 0 128
node analyze9.mjs results9.jsonl                # scores against results8.jsonl in this directory
```

`analyze9.mjs` compares against whatever is in `results8.jsonl`. Both baselines
are here: swap `results9base.jsonl` in for the same-session comparison the report
leads with, or leave round 8's stored run in place for the cross-session one.

## Files

| file | what it is |
| --- | --- |
| `roidump.mjs` / `roidump.json` | the two shipped primary passes over round 8's 17 failures + 20 controls, dumping **every word box with its confidence** — the evidence that a failed pass still locates the label |
| `roi.mjs` | the ROI derivation prototype, mirrored by `deriveLabelRoi` in `src/ocr.ts` |
| `roicheck.mjs` | what ROI the rule derives per image, and how much of the frame it covers |
| `spancheck.mjs` | the located label's span as a fraction of frame width — where `CROP_TRIGGER_SPAN_FRACTION` comes from |
| `roipeek.mjs` | prints the raw boxes for named images |
| `croplab.mjs` / `croplab.json` / `croplab2.json` | the crop-scale sweep: crop to the ROI, recognise it at several target text heights, plain and boosted |
| `run9.mjs` | round 8's real-browser runner, pointed at this worktree's build and round 8's images |
| `analyze9.mjs` | the scoring and every breakdown in the report |
| `results9.jsonl` | the 128-image run **with** the crop stage |
| `results9base.jsonl` | the 128-image run with `src/ocr.ts` restored from `main`, same session, same machine |
| `results8.jsonl` | round 8's stored run, copied here so this directory is self-contained |
| `plan.json` / `meta.json` | round 8's case plan and measured geometry, copied for the same reason |

## The caveat round 8 asked to carry forward

Font is perfectly confounded with distance in groups `A-dist`, `B-persp` and
`C-bend` (round 8, section 56). Nothing in this round is a font result, and the
distance claims here rest on the same `D-combo` and clean-background controls
that round 8 used.
